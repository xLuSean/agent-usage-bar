# UI spec

這份規格是 Claude 與 Codex 兩個 provider **必須一致**的部分。實作在
`UsageMeterCore/Gauge/GaugeStyle.swift`（語意）與 `AgentUsageBar/Gauge/GaugeImageRenderer.swift`（繪製）。

## 1. 選單列量表

**量表顯示最短的那個時間窗**（Claude 是 5 小時窗），不是「目前綁定的限制」。

原本的設計要求顯示 `is_active` 的窗。實際使用後改掉：週窗可以連續好幾天都是綁定限制，量表因此停在一個幾乎不動的數字上，而**五小時窗 —— 真正會在一小時內擋住你、而且快到會重設的那個 —— 完全看不到**。一個掃一眼的儀表應該追快速變動的量。綁定限制仍然顯示在 popover 裡，標著「目前綁定」，那裡有空間讀。


窄型直立外框，內部由下往上填色。圖片尺寸 21 × 18 pt：左側 7.5 pt 是身分字母，右側是量表框。

**填色高度代表已消耗的比例**，量表隨消耗往上長，不是往下退。兩個供應商都以「已用」回報，中間再轉換一次是混淆的來源。

## 2. 顏色的分工

顏色被賦予兩種語意（身分 vs 嚴重度），同一元素無法兼顧，因此拆到不同部位：

| 部位 | 承載 | 可客製 |
|---|---|---|
| 外框／字母 | **身分**（哪個供應商） | 是，預設調色板 |
| 內部填色 | **嚴重度** | 否 |
| 填色高度 | 已用比例 | 否 |

身分色票刻意排除綠、橘、紅 —— 那三個顏色是填色的語彙，外框若能變成橘色就會跟填色想說的話撞在一起。

## 3. 嚴重度：一套刻度，兩個供應商

顏色**只看已用百分比**，一律使用下表，兩個供應商共用：

| 已用 | 等級 | 顏色 |
|---|---|---|
| 0–49% | ok | 綠 |
| 50–79% | caution | 橘 |
| 80–99% | critical | 紅 |
| 100% | exhausted | 紅色斜線 |
| 無資料 | unknown | 灰色橫槓 |

### 3.1 為什麼不採用各家自己的嚴重度判定

Provider 可能提供自己的限制狀態 metadata；Claude 現行 `/usage` 文字沒有 severity 欄位，Codex App Server 的 `rateLimitReachedType` 則另列在詳情。**無論是否提供，都不得用來決定共用顏色。**

各家對「什麼程度算要注意」的判定不會一致。若各自採用，同一個橘色在兩個量表上就回答了不同的問題，使用者必須同時記住兩套刻度才讀得懂一排選單列 —— 那等於取消了兩個量表共用視覺語言的意義。

用一個合成情境說明：若某個窗已跨過共用的注意門檻，但伺服器仍判定為 `normal`，進度條就會是綠的，旁邊的百分比卻在警示區。數字和顏色會講不同的事。

`UsageWindow.severity` 因沒有 UI 或診斷出口而移除；舊 Snapshot 帶著這個欄位仍可還原。共用顏色只由百分比決定，Codex 的 `rateLimitReachedType` 則因有獨立 UI 消費者而保留。

### 3.2 兩個細節

橘而不是黃：黃色在淺色選單列上會消失。

100% 畫成斜線而不是滿格：滿格的量表看起來像「很充足」，那正好是相反的意思。

## 4. 非顏色的身分線索（硬性要求）

顏色**不得是唯一的資訊載體**。每個供應商在量表左側有一個字母（Claude = `C`，Codex = `X`）。色覺障礙者、或使用者把兩個外框顏色選得太接近時，仍分得出來。

「要不要有」不可討論，「用哪種形式」可由實作決定。

## 5. 資料狀態的視覺區隔

| 狀態 | 外框 | 填色 | 附加標記 |
|---|---|---|---|
| current | 實線 | 正常 | — |
| refreshing（有舊值） | 實線 | 正常 | — |
| stale | 實線 | 40% 透明度 | 右上角橘色三角 |
| throttled（上游有可靠限流資訊時） | 實線 | 橫條紋 | — |
| unavailable / starting | 虛線 | 無 | 中央灰色橫槓 |

三條規則：

- **未知絕不畫成 0%。** 虛線空框加灰槓，跟「已用完」的紅色斜線是明確不同的兩個記號。
- **有可靠限流資訊時，限流與一般過期必須可區分。** 條紋 vs 橘色三角。現行 live provider 不保證能取得 429／恢復時間，因此不得為了畫出 throttled 而猜測。
- **極低的百分比仍要看得見。** 最小填色高度 2 pt，1% 不會消失成空框。

## 6. 深淺色

量表**不是** template image（它刻意帶顏色），所以 AppKit 不會自動適應選單列外觀。控制器監聽 `effectiveAppearance` 變化並重繪，所有顏色使用動態 system color。

`--render-sheet` 會輸出所有狀態 × 兩個供應商 × 淺色／深色的對照圖，用來檢查這件事。

## 7. 多供應商呈現

兩種版面，設定中可切換：

- **分開顯示**：每個供應商一個 `NSStatusItem`，並排。各自獨立降級 —— 一邊不可用不影響另一邊。
- **合併顯示**：兩個量表畫在同一個圖示裡，寬度約減半。**兩個身分線索都保留**（各自的字母與外框顏色）。字母不縮小 —— 縮字母才會真的看不清。

合併圖示點擊後同時顯示所有已啟用供應商，順序固定且各自保留狀態。設定頁的「選單列顯示」也必須回報「合併圖示中」，不能因個別 `NSStatusItem` 在合併模式本來就不存在而誤報「未啟用」。

每個 `NSStatusItem` 必須有**各自的 `autosaveName`**。沒有的話 AppKit 會從 App 名稱推導出同一個名字，兩個項目共用一筆位置記錄，其中一個會不見。

## 8. 兩者皆停用

必須保留一個**中性的預設圖示**作為入口。否則使用者把兩個都關掉之後，選單列沒有任何圖示 —— 也就再也打不開設定，把自己鎖在外面。

這個圖示是中性的：停用是使用者的選擇，不是需要注意的問題，不得畫成錯誤或耗盡。

## 9. 無障礙

每個狀態都必須有可理解的 VoiceOver label，內容包含供應商、時間窗、已用百分比、資料狀態，以及失敗時的原因或恢復時間。實作在 `GaugeStyleResolver.accessibilityLabel`，有單元測試涵蓋每個狀態。

## 10. 詳情面板

至少顯示：各時間窗的已用％與重設時間、資料狀態、最後成功更新時間、資料來源、限流時的預計恢復時間。以及兩個必須永遠可達的動作：**重新整理**與**結束 App**。

那兩個按鈕固定在內容區之外。面板先依內容自然高度展開；目前螢幕放得下時直接完整顯示、不出現 scrollbar。只有內容真的超過螢幕可用高度時才啟用捲動退路，而 App 沒有 Dock 圖示 —— 「結束 App」是唯一的離開方式，不能掉到摺線以下。

時間窗的數量是**不定的**（5 小時、7 天，加上任意數量的 per-model 週窗），版面不得假設剛好兩個。

列的排版可以共用，但缺漏欄位的意思不可硬套同一套文案。Claude session 只有在 decoder 已確認 `0%` 且沒有 reset 時，才顯示「尚未提供重設時間」；Codex 的 `resetsAt` 是 App Server 的 optional 欄位，缺少時維持中性的「重設時間未提供」。共用 `WindowRow` 只負責畫出 provider 已決定的文字，不自行猜測原因。

## 11. 設定視窗

每個 provider 的外框顏色、更新頻率、資料狀態與選單列位置使用同一組對齊欄位。更新頻率的「建議」標籤仍依 provider 判斷；**目前兩邊都是 10 分鐘**，但 Claude 依賴輪詢、Codex 是推播外的保險查詢，未來可以各自調整，不能把理由合併成一個全域常數。

顯示語言由 App 自己的設定管理，可在**繁體中文**與 **English** 間立即切換並保存。這是 UI 偏好，不影響 provider、查詢、快取或資料狀態。所有使用者可見文案、日期／相對時間、選單列提示與 VoiceOver 必須使用同一個語言值；首次安裝預設繁體中文。

設定另有「診斷紀錄」頁，依新到舊顯示失敗時間、供應商與固定錯誤類型。每列可個別展開；展開後顯示由 App 封閉原因代碼產生的完整詳細訊息，並提供「複製訊息」按鈕與成功回饋。多列可同時展開，展開與已複製狀態只屬於當下視窗，不持久化。舊版紀錄沒有詳細原因時必須明示當時未保存，不得猜測。保存期限為 3／5／7 天，預設 5 天；「清除紀錄」只刪除錯誤紀錄，不動用量快照、供應商設定或期限選擇。空狀態須說明尚無錯誤，頁尾必須明載不保存原始回應、憑證、執行檔路徑或 provider 任意文字。

設定視窗關閉後可重用，但再次開啟必須出現在使用者目前所在的 Space。設定中的選單列狀態描述實際呈現位置（個別圖示、合併圖示、被隱藏或放不下），不能把「啟用」與「有個別 status item」混為同一件事。
