# UI spec

這份規格是 Claude 與 Codex 兩個 provider **必須一致**的部分。實作在
`UsageMeterCore/Gauge/GaugeStyle.swift`（語意）與 `AgentUsageBar/Gauge/GaugeImageRenderer.swift`（繪製）。

## 1. 選單列量表

**每家同時顯示兩個時間窗：左側 5 小時，右側所有模型共用的 7 天額度。** 不依用量高低或 `is_active` 交換位置，也不拿模型專屬的週額度補進一般週額度。

圖片固定 27 × 18 pt：左側保留 C／X，右側是一個 18 × 16 pt 的共用長方形外框，中間只有一條 1 pt 分隔線；兩半沒有各自的外框或額外間距。Claude 依 `kind` 選擇 `session`／`weekly_all`；Codex 依明確回報的 300／10,080 分鐘辨識，不能把 `primary`／`secondary` 的位置當成期間。

**填色高度代表已消耗的比例**，量表隨消耗往上長，不是往下退。兩個供應商都以「已用」回報，中間再轉換一次是混淆的來源。

每個時間窗的剩餘額度為 10% 以下（含 10%）時，只在該半格顯示剩餘數字與 `%`，上下排列並以淡紅色底提示低額度；兩半可同時顯示不同數字，耗盡時明示 0%。共用外框、中線、字母與整張圖的寬度都不變。資料過期、已過重設時間或限流時保留原本的填色與狀態標記，不用數字蓋過狀態；耗盡的非最新讀數仍以紅色斜線呈現。每個時間窗的已用與剩餘整數百分比也在滑鼠提示、VoiceOver 與詳情面板顯示。

明確回報的 0% 為空白半格；尚未取得讀數為灰色橫槓；Claude 的結構化清單未列出該限制時為灰色斜線。後兩者都不能解讀成 0% 或無上限。缺一個時間窗時，另一半仍保留自己的讀數。

## 2. 顏色的分工

顏色被賦予兩種語意（身分 vs 嚴重度），同一元素無法兼顧，因此拆到不同部位：

| 部位 | 承載 | 可客製 |
|---|---|---|
| 外框／字母 | **身分**（哪個供應商） | 是，預設調色板 |
| 內部填色 | **嚴重度** | 否 |
| 填色高度 | 已用比例 | 否 |

身分色票刻意排除綠、橘、紅 —— 那三個顏色是填色的語彙，外框若能變成橘色就會跟填色想說的話撞在一起。

## 3. 嚴重度：一套刻度，兩個供應商

顏色**只看已用百分比**，一律使用下表，兩個供應商共用：

| 已用 | 等級 | 顏色 |
|---|---|---|
| 0–49% | ok | 綠 |
| 50–79% | caution | 橘 |
| 80–99% | critical | 紅 |
| 100% | exhausted | 最新讀數顯示剩餘 0%；其他狀態為紅色斜線 |
| 無資料 | unknown | 灰色橫槓 |

### 3.1 為什麼不採用各家自己的嚴重度判定

Provider 可能提供自己的限制狀態 metadata；Claude 的結構化用量報告每一列都帶 `severity`，App 刻意不讀，Codex App Server 的 `rateLimitReachedType` 則另列在詳情。**無論是否提供，都不得用來決定共用顏色。**

各家對「什麼程度算要注意」的判定不會一致。若各自採用，同一個橘色在兩個量表上就回答了不同的問題，使用者必須同時記住兩套刻度才讀得懂一排選單列 —— 那等於取消了兩個量表共用視覺語言的意義。

用一個合成情境說明：若某個窗已跨過共用的注意門檻，但伺服器仍判定為 `normal`，進度條就會是綠的，旁邊的百分比卻在警示區。數字和顏色會講不同的事。

`UsageWindow.severity` 因沒有 UI 或診斷出口而移除；舊 Snapshot 帶著這個欄位仍可還原。共用顏色只由百分比決定，Codex 的 `rateLimitReachedType` 則因有獨立 UI 消費者而保留。

### 3.2 兩個細節

橘而不是黃：黃色在淺色選單列上會消失。

100% 的最新讀數顯示剩餘 0%；過期或限流讀數使用紅色斜線，避免把「已耗盡」看成「很充足」。

## 4. 非顏色的身分線索（硬性要求）

顏色**不得是唯一的資訊載體**。每個供應商在量表左側有一個字母（Claude = `C`，Codex = `X`）。色覺障礙者、或使用者把兩個外框顏色選得太接近時，仍分得出來。

「要不要有」不可討論，「用哪種形式」可由實作決定。

## 5. 資料狀態的視覺區隔

| 狀態 | 外框 | 填色 | 附加標記 |
|---|---|---|---|
| current | 實線 | 正常 | — |
| refreshing（有舊值） | 實線 | 正常 | — |
| stale | 實線 | 40% 透明度 | 右上角橘色三角 |
| throttled（上游有可靠限流資訊時） | 實線 | 橫條紋 | — |
| unavailable / starting | 虛線 | 無 | 中央灰色橫槓 |

三條規則：

- **未知絕不畫成 0%。** 整家無資料時是虛線框加灰槓；只缺一窗時，在該半格畫灰槓。可信已用 0% 為空白；最新的耗盡讀數為剩餘 0%，其他狀態為紅色斜線。
- **有可靠限流資訊時，限流與一般過期必須可區分。** 條紋 vs 橘色三角。現行 live provider 不保證能取得 429／恢復時間，因此不得為了畫出 throttled 而猜測。
- **極低的百分比仍要看得見。** 最小填色高度 2 pt，1% 不會消失成空框。

重繪時若個別窗的重設時間超過 60 秒寬限，該半格變淡並加橘色小三角，提示說明正在等待更新；另一個尚未到期的窗不跟著降級。

## 6. 深淺色

量表**不是** template image（它刻意帶顏色），所以 AppKit 不會自動適應選單列外觀。控制器監聽 `effectiveAppearance` 變化並重繪，所有顏色使用動態 system color。

`--render-sheet` 會輸出所有狀態 × 兩個供應商 × 淺色／深色的對照圖，用來檢查這件事。

## 7. 多供應商呈現

兩種版面，設定中可切換：

- **分開顯示**：每個供應商一個 `NSStatusItem`，並排。各自獨立降級 —— 一邊不可用不影響另一邊。
- **合併顯示**：兩家的雙時間窗畫在同一個圖示裡，只省去一份系統留白，仍保留各自的字母與外框顏色。

每家在兩種版面都為 27 pt 寬；合併版項目間距 3 pt，兩家總寬為 57 pt。控制器另加 8 pt 系統留白，所以兩家合併佔 65 pt，分開共佔 70 pt。低額度、耗盡、失敗及額度恢復都不改變寬度。

合併圖示點擊後同時顯示所有已啟用供應商，順序固定且各自保留狀態。設定頁的「選單列顯示」也必須回報「合併圖示中」，不能因個別 `NSStatusItem` 在合併模式本來就不存在而誤報「未啟用」。

每個 `NSStatusItem` 必須有**各自的 `autosaveName`**。沒有的話 AppKit 會從 App 名稱推導出同一個名字，兩個項目共用一筆位置記錄，其中一個會不見。

## 8. 兩者皆停用

必須保留一個**中性的預設圖示**作為入口。否則使用者把兩個都關掉之後，選單列沒有任何圖示 —— 也就再也打不開設定，把自己鎖在外面。

這個圖示是中性的：停用是使用者的選擇，不是需要注意的問題，不得畫成錯誤或耗盡。

## 9. 無障礙

每個狀態都必須有可理解的 VoiceOver label，內容包含供應商、時間窗、已用百分比、資料狀態，以及失敗時的原因或恢復時間。實作在 `GaugeStyleResolver.accessibilityLabel`，有單元測試涵蓋每個狀態。

## 10. 詳情面板

至少顯示：各時間窗的已用％與重設時間、資料狀態、最後成功更新時間、資料來源、限流時的預計恢復時間。Codex Token 區塊標題固定含有供應商名稱：「Codex 帳號 Token 用量」／「Codex account token usage」，讓捲動後的區塊仍能獨立辨識。Codex 有可信 `account/usage/read` 時，另顯示今天、累積 Token、最高單日 Token、每日長條圖、最新 bucket 的「資料統計至」日期與 Token 自己的更新時間；今天尚無 bucket 時顯示「尚未回報」，不得假裝成 0。圖表預設最近 30 天，設定可選 5／10／15／20／30／60 天，而且只調整顯示切片；滑鼠移到任一長條時，直接在圖內顯示該 bucket 的完整日期與 Token 數，不增加平常的面板高度。沒有可信帳號統計時明示 Token 統計不可用，但不得把 quota 一起降級。還要有兩個必須永遠可達的動作：**重新整理**與**結束 App**；重新整理必須同時要求額度與 Token 統計。

那兩個按鈕固定在內容區之外。面板先依內容自然高度展開；目前螢幕放得下時直接完整顯示、不出現 scrollbar。只有內容真的超過螢幕可用高度時才啟用捲動退路，而 App 沒有 Dock 圖示 —— 「結束 App」是唯一的離開方式，不能掉到摺線以下。

面板頂端固定保留 5 小時與 7 天兩列，0% 仍顯示。缺資料時說「尚無資料」；Claude 清單明確未列出時說「未列出此限制」，不顯示虛構數字。其後仍可列出不定數量的模型週窗及其他期間。`is_active` 只代表伺服器替單值指示器選中的列，介面不再標示「目前綁定」。

### 10.1 每一列可以各自收合

每個有讀數的時間窗標題列是一個按鈕，點一下把那一列收成一行，再點一下展開。兩個 provider 共用同一個 `WindowRow`，行為一致。缺值提示列維持一行，不提供收合。

| | 展開 | 收合 |
|---|---|---|
| 名稱、已用百分比 | 顯示 | 顯示 |
| 進度條 | 顯示 | 不顯示 |
| 剩餘百分比與重設時間 | 顯示 | 不顯示 |

**收合不隱藏數字。** 這是它可以被記住、而且不需要「快用完時自動展開」這類規則的原因：收起來的那一列仍然印著百分比，資料不可信時也照樣變淡。代價是收合的列沒有顏色線索 —— 嚴重度的顏色在進度條上，而進度條正是被收掉的部分。

預設：5 小時與 7 天展開；模型專屬的週上限收合；這個版本沒見過的額度種類展開，第一次出現時應該被完整看到。

收合狀態以 provider 加時間窗身分為鍵，只保存與預設不同的部分，跨啟動記住，兩種選單列版面共用同一份。這是 popover 裡唯一會被保存的操作。其餘偏好仍然只在設定視窗，因為 transient popover 一失焦就關閉，不適合「改了再看結果」；收合一列的結果就是 popover 本身，所以不受這個理由限制。

時間窗身分含有 provider 提供的標籤，因此鍵在寫入偏好前要通過與其他 provider 文字相同的安全檢查，筆數也有上限。

收合或展開會改變內容高度。面板開啟時依內容量出的高度是一個固定數字，所以每次收放後控制器都重新量一次並調整 popover；只有在需要切換捲動退路時才重建內容。那兩個必須永遠可達的按鈕仍然固定在內容區之外。

列的排版可以共用，但缺漏欄位的意思不可硬套同一套文案。Claude session 只有在 decoder 已確認 `0%` 且沒有 reset 時，才顯示「尚未提供重設時間」；Codex 的 `resetsAt` 是 App Server 的 optional 欄位，缺少時維持中性的「重設時間未提供」。共用 `WindowRow` 只負責畫出 provider 已決定的文字，不自行猜測原因。Codex Token 的日期是資料截止日，不得寫成「即時更新」；唯讀帳號統計與不掃描本機 task 的權限邊界保留在 README／資料來源文件，不在窄小的 popover 重複佔用空間。

## 11. 設定視窗

每個 provider 的外框顏色、更新頻率、資料狀態與選單列位置使用同一組對齊欄位。一般更新頻率的「建議」標籤仍依 provider 判斷；Claude 與 Codex 額度目前都建議 10 分鐘，但 Claude 依賴輪詢、Codex 是推播外的保險查詢，理由不能合併成一個全域常數。Codex 另顯示「Token 更新頻率」（15／30 分鐘、1／2／3／6 小時，1 小時為建議值）與「Token 圖表範圍」，兩者不能混為同一設定。

顯示語言由 App 自己的設定管理，可在**繁體中文**與 **English** 間立即切換並保存。這是 UI 偏好，不影響 provider、查詢、快取或資料狀態。所有使用者可見文案、日期／相對時間、選單列提示與 VoiceOver 必須使用同一個語言值；首次安裝預設繁體中文。

設定另有「診斷紀錄」頁，依新到舊顯示失敗時間、供應商與固定錯誤類型。每列可個別展開；展開後顯示由 App 封閉原因代碼產生的完整詳細訊息，並提供「複製訊息」按鈕與成功回饋。多列可同時展開，展開與已複製狀態只屬於當下視窗，不持久化。舊版紀錄沒有詳細原因時必須明示當時未保存，不得猜測。保存期限為 3／5／7 天，預設 5 天；「清除紀錄」只刪除錯誤紀錄，不動用量快照、供應商設定或期限選擇。空狀態須說明尚無錯誤，頁尾必須明載不保存原始回應、憑證、執行檔路徑或 provider 任意文字。

設定視窗關閉後可重用，但再次開啟必須出現在使用者目前所在的 Space。設定中的選單列狀態描述實際呈現位置（個別圖示、合併圖示、被隱藏或放不下），不能把「啟用」與「有個別 status item」混為同一件事。
